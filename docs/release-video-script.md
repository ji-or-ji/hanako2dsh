# Hanako2DSH 发布片 · 分场脚本 v1

## 基本信息

| 项 | 值 |
| --- | --- |
| 渠道 | B站，横屏 16:9 |
| 规格 | 1920×1080 / 30fps / h264（WebM 渲出后 h264_mf 转码）/ 约 65s |
| 定位 | 产品发布片，不露人 |
| 目标 | 走量。自指奇观开场抓留存，靠完播与互动拿推流 |
| 旁白 | 季自录（RCV 处理后），暂缺；本文按旁白稿切字幕，时长待录音后对齐 |
| 字幕 | 硬字幕 + 外挂 SRT 双份 |
| 视觉基调 | 暖米底 #F4EFE7 / 深墨字 #1F1B16 / 低饱和蓝点缀，与 Hana 主题一致 |
| 渲染 | HyperFrames 本地（Edge + 本机 FFmpeg），GSAP 本地化，全离线 |

**结构一句话**：自指开场 → 痛点 → 转折 → 三个功能 → 回到自指 → 落版。

## 逐段详述

### S0 钩子（0:00–0:05）

- 画面：黑场起手，0.3s 内亮起一片"AI 正在干活"的抽象视觉——成行文字高速流出、任务卡片逐个打勾、状态灯从灰转绿。不要出现具体产品名，先给奇观。
- 动效：文字滚动 8–12 行/秒（快到看不清内容，只看得出"在狂奔"），卡片打勾带一点弹性，整体轻微闪烁。
- 旁白：**这段视频，是我让两个 AI 自己做出来的。**
- 字幕切分：
  - 0:00.6–0:02.6 「这段视频，是我让两个 AI 自己做出来的」
- 备注：这是全片的钩子，第一秒必须让人看不出这是什么，却想接着看。

### S1 痛点（0:05–0:14）

- 画面：分屏，左侧一个 DSH 窗口，右侧一个 Hana 窗口，中间是光标在两个窗口间来回跳。复制 → 切窗口 → 粘贴 → 再切回来 → 盯着进度条。
- 动效：光标移动要有"被拖来拖去"的烦躁感，节奏偏快但不失清晰；进度条走得很慢，形成对比。
- 旁白：**但在这之前，每次想让它干活，我得先切到 DSH，复制结果，再切回来，粘贴。**
- 字幕切分：
  - 0:05.4–0:09.4 「但在这之前，每次想让它干活」
  - 0:09.6–0:13.4 「我得先切到 DSH，复制结果，再切回来，粘贴」
- 备注：痛点描述要对"没用过 DSH"的人也成立，所以重点是"来回搬"这个动作，不是 DSH 本身。

### S2 转折（0:14–0:20）

- 画面：画面切到 Hana 的界面，顶栏一个 `DSH` 页签由暗转亮，被点开，里面是一个有内容在动的 DSH 界面。
- 动效：页签亮起用一次干净的淡入 + 微光晕；界面展开像一块布帘拉开。
- 旁白：**直到有一天，它住进了 Hana。**
- 字幕切分：
  - 0:14.6–0:17.8 「直到有一天，它住进了 Hana」
- 备注：这句话是整片的分水岭，画面和声音都要在这里"换气"。

### S3 镜像（0:20–0:33）

- 画面：页签内的 DSH 在实时交互：输入框打字，结果实时出现；鼠标在里面点，界面有反馈。
- 动效：输入、回显要流畅，强调"实时"。
- 旁白：**这一个页签里，是真正在跑的 DSH，不是截图。你在里面点、在里面聊，都算数。**
- 字幕切分：
  - 0:20.6–0:24.6 「这一个页签里，是真正在跑的 DSH」
  - 0:24.8–0:28.6 「不是截图。你在里面点、在里面聊，都算数」
- 备注：此段优先真实录屏。录屏画面嵌在一个 HyperFrames 生成的"屏幕框"里，周围配色走 Hana 主题。

### S4 派活（0:33–0:44）

- 画面：在 Hana 输入一句话 → 出现「已派单」→ 镜头"离开"（画面轻微移开或淡出）表示你走了 → 结果自己飘回对话。
- 动效：派单时一个短促的确认动效；"你走了"用一点点时间流逝感（光影变化）；结果飘回用一次柔和的滑入。
- 旁白：**更省事的是，你甚至不用看着它。一句话派出去，任务在后台跑，做完了自己回来找你。**
- 字幕切分：
  - 0:33.6–0:37.4 「更省事的是，你甚至不用看着它」
  - 0:37.6–0:42.4 「一句话派出去，任务在后台跑，做完了自己回来找你」
- 备注：这段是产品最核心的情绪点——你不在场，活自己完成了。节奏上要给"离开"留一点空白。

### S5 时间线（0:44–0:54）

- 画面：侧栏时间线，每一次工具调用一行，状态灯、实时进度，右下角一个「急停」。
- 动效：行逐条生长，状态灯依次由灰转绿，进度条推进。
- 旁白：**它每一步在干什么，你都看得见。哪一步卡住了，按一下就能停下来。**
- 字幕切分：
  - 0:44.6–0:48.4 「它每一步在干什么，你都看得见」
  - 0:48.6–0:52.4 「哪一步卡住了，按一下就能停下来」
- 备注：优先真实录屏，真实时间线的说服力最强。

### S6 自指（0:54–0:59）

- 画面：镜头拉远 / 淡回，回到开场那片"AI 干活"的画面，形成首尾呼应。
- 动效：一次干净的环绕或推远，让开场和结尾的视觉咬合上。
- 旁白：**所以，你刚看的这一分钟，也是这么来的。**
- 字幕切分：
  - 0:54.6–0:58.6 「所以，你刚看的这一分钟，也是这么来的」
- 备注：走量版把自指放在开头和结尾各一次，不靠"最后揭底"的单一反转。

### S7 落版（0:59–1:05）

- 画面：Hanako2DSH 字样居中，下方版本号与仓库地址，底部一行 Apache-2.0。
- 动效：淡入，留足停留时间（发布片落版别急着切）。
- 旁白：无，或一句「Hanako2DSH」。
- 字幕：仓库地址 / 版本信息。

## 素材与复刻清单

- **必须复刻（HyperFrames 生成）**：S0、S1、S6、S7，以及 S3–S5 的"屏幕框"与背景层。
- **优先真实录屏**：S3、S4、S5 的功能演示。用真实录屏能省掉"复刻 Hana 与 DSH 界面"这件事，而它本来是整片最重的工作量。
- **录屏失败时的 fallback**：改用复刻 UI，工作量显著上升，且可信度略降。
- **字体**：Microsoft YaHei（本机已验证可渲染中文，无豆腐块）。

## 制作与迭代策略

- 每次渲染有约 2.5 分钟固定开销（浏览器启动 + 校准），捕帧按帧数线性增长。65 秒片单轮预计 8–10 分钟。
- 所以迭代靠 `check --snapshots` 盯局部帧，满意了再渲全片，不要每改一处就渲一遍。
- 旁白未录前，先按"每字约 0.22 秒"给段落估时，把片子撑起来；录音后按实际时长回填 `data-duration` 与字幕时间轴。
- 中间产物保留 `.webm`，最终交付 `.mp4`（h264 + faststart）。
